# Software decoding baseline first, followed by FFmpeg `ounce` VideoDecoder wrapper

The Switch 2 port preserves software decoding on FFmpeg 7.1.5 and mpv 0.36.0 (`hwdec=no`, with commit `14ef15c5f`'s presentation pacing fix) as its known-good compatibility baseline and recovery path so the first usable beta (`#20`) is never delayed or destabilized. Hardware video decoding (`#14`–`#16`) is pursued on an isolated branch (`feat/switch2-viddec`) as a reusable **FFmpeg decoder wrapper** (`wrapper_name = "ounce"`, exposed by unmodified libmpv 0.36.0 as `hwdec=ounce-copy`) backed by `libounce`'s high-level `VideoDecoder` API (`03af07a739a9a3b48704500cffcd6155692cc194`), avoiding raw service wrappers or `--wrap` archive interception.

Stage 1 uses bounded `AV_PIX_FMT_NV12` CPU copy-back (`h264_ounce` up to 1080p60 including coded `1920x1088` as the first independently shippable vertical slice, followed individually by `vp9_ounce` `<=1080p60`, qualified `vp8_ounce`, and `av1_ounce` `<=4K30` block-linear) and routes HEVC, `>1080p` H.264/VP9, unsupported profiles/chroma, unqualified 10-bit, and unknown metadata to software decoding. Stage 2 reference-backed pitch-linear `AVFrame` (`AVBufferRef` in `buf[0]`) and Stage 3 GPU-direct sharing (`#22`) are independent follow-ons evaluated only after Stage 1 device qualification when justified by measurements, while retaining `hwdec=no` as automatic stall-hardened fallback.
